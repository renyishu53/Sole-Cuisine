SoloChef · 双工作流流程图

主规划工作流 SoloChefWorkflow（从零生成周计划）＋ 修改工作流 PlanRevisionWorkflow（局部精准调整）。节点定义取自 backend/app/ai/workflow.py 与 revision_workflow.py 源码。

起止 / 同步 约束 / 路由 检索 协调 / 归约 领域智能体 / 分支 计划组装 校验 终稿

① 主规划工作流 SoloChefWorkflow

定位：高成本 · 并行 · 可断点续传 ｜ 11 节点 + 两处并行 ｜ 编译时注入 InMemorySaver checkpointer

并行①：graph_retriever ∥ vector_retriever 双路检索；并行②：meal_agent ∥ shopping_agent ∥ budget_agent 三领域并行。并行写入靠 Annotated[list, operator.add] 归约器（domain_results / specialist_outputs / trace）零冲突。校验节点内含确定性营养达成率校验与三级自愈。

② 修改工作流 PlanRevisionWorkflow

定位：低成本 · 条件路由 · 单分支 ｜ 8 节点（路由1 + 分支5 + 后处理2）｜ 一次性 ainvoke，无 checkpointer，只产预览不落库

5 个分支节点全部绑定同一个 _execute_selected_branch——路由的价值在于声明受影响能力（requires）而非跑不同代码。按影响面分级：update_budget 仅路由到 BUDGET；adjust_macro_target / exclude_ingredient 路由到全部能力。橙色虚线为条件路由边。

两工作流对比

维度① 主规划工作流 SoloChefWorkflow② 修改工作流 PlanRevisionWorkflow
本质计算整段推倒重来（高成本）局部精准手术（低成本）
节点数11 节点 + 两处并行8 节点（路由1 + 分支5 + 后处理2）
LLM 调用约束解析 + 3 领域智能体 + 生成（多次）不调 LLM 生成新菜，仅确定性应用
检索双路（Neo4j 图谱 ∥ Chroma 向量）无检索
并行模型图拓扑声明并行（add_edge）条件路由单分支（conditional_edges）
Checkpoint注入 InMemorySaver，支持 resume + 流式增量无，一次性 ainvoke
落库时机直接生成计划并落库只产预览草稿，等 confirm 才落库
触发场景“生成一周膳食计划”“周三晚餐换鸡胸肉”“预算降到 80 元”

两者通过「预览 / 确认分离」协议衔接：修改工作流先生成 before/after diff 预览存 ChatMessage.payload，用户 confirm 后才调用 derive_plan_with_modifications 落库，避免 AI 自作主张直接改库。问答服务（问 SoloChef）不属于 LangGraph 计划工作流。
