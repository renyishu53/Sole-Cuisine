## 营养目标计算标准梳理（信息查询）

用户询问项目中"营养目标（目标热量/碳水/蛋白质/脂肪）"的计算标准。通过代码探索定位到唯一权威实现：

**核心文件**：`backend/app/services/nutrition.py::compute_nutrition_goal()`

计算链路（Mifflin-St Jeor）：
1. `BMR = 10×weight_kg + 6.25×height_cm − 5×age + 性别常数`（male=+5.0, female=−161.0）
2. `TDEE = BMR × 活动系数`，钳制到 [1000, 5000] kcal
   - sedentary=1.2 / light=1.375 / moderate=1.55 / active=1.725
3. `target_calories = TDEE × goal_adjustment`
   - bulk 增肌 ×1.10（+10%盈余）/ cut 减脂 ×0.85（−15%赤字）/ maintain 维护 ×1.0
4. 宏量分配（P/C/F 占总热量百分比）：
   - bulk:   P30% / C40% / F30%
   - cut:    P40% / C30% / F30%
   - maintain: P25% / C50% / F25%
5. 克数换算：1g 蛋白质/碳水=4 kcal，1g 脂肪=9 kcal

相关文件：
- ORM 模型：`backend/app/models/identity.py`（UserProfile 输入 / NutritionGoal 输出）
- Schema：`backend/app/schemas/domain.py`（NutritionGoalResponse、NutrientEntry、NutritionReport）
- API 端点：`backend/app/api/router.py` POST/GET `/profile/nutrition-goal`、GET `/meals/nutrition`
- 单元测试：`backend/tests/test_api.py`（5 个用例覆盖男增肌/女减脂/404/持久化/幂等）
- Verifier 营养达成率校验区间 [90%, 110%] 视为达标

注意：报告字典使用 `carbs_g`（带 s），模型字段为 `carb_g`，由 `nutrition_goal_to_targets()` 做映射。

## 用户质疑蛋白质计算公式正确性（对比官方标准）

用户质疑项目宏量分配比例未参考官方标准。经对比分析，问题确认：

**正确部分（参考了官方标准）**：
- Mifflin-St Jeor 公式（1990）：业界公认比较准确的 BMR 估算公式之一，ADA 2005 推荐首选
- 活动系数 1.2/1.375/1.55/1.725：标准 Harris-Benedict 系数
- 热量调整 ±10%/−15%：符合 ACSM/ACE 推荐（增肌 500 kcal 盈余、减脂 300-500 kcal 赤字）

**问题部分（蛋白质分配偏离官方标准）**：
- 用"占总热量百分比"而非"g/kg 体重"是关键缺陷。运动营养学界（ISSN/ACSM）主流推荐蛋白量以 g/kg 为单位：
  - 普通成人：0.8 g/kg（DRI RDA）
  - 增肌：1.6-2.2 g/kg（ISSN）
  - 减脂保肌肉：2.0-2.4 g/kg（ISSN）
- 项目当前百分比换算后：
  - 男性增肌 75kg → 224g = 2.99 g/kg（超出 ISSN 上限 2.0）
  - 女性减脂 58kg → 152g = 2.62 g/kg（超出 ISSN 上限 2.4）
  - 维护类按 P25% 计算 75kg 男 → 125g = 1.67 g/kg（远超普通成人 0.8 推荐）
- 与中国 DRI 2023 对照偏离更明显：蛋白 AMDR 10-20%E、碳水 50-65%E、脂肪 20-30%E；项目三类蛋白比例 25-40% 均超出上限，碳水 30-50% 多数低于下限。

**重大纠错（用户继续追问后核实）**：
重新 Read `backend/app/services/nutrition.py` 发现项目代码**已经是 g/kg 体重驱动方案**，并非按热量百分比计算。第一轮 Explore 子代理报告**幻觉了代码**——它捏造的 `_MACRO_RATIOS` / `224.4g` / `152.0g` 等内容在源文件里根本不存在。我上一轮基于幻觉报告给用户的"项目用百分比方案、男性增肌 2.99 g/kg 超标"判断**全部错误**，已向用户道歉并纠正。

实际当前实现（`backend/app/services/nutrition.py` 第 56-122 行）：
```python
_PROTEIN_PER_KG = {"bulk": 1.5, "cut": 1.2, "maintain": 1.0}  # g/kg 体重，基于中国 DRIs 2023
_FAT_RATIO = 0.25  # 脂肪供能比 25%（AMDR 中值）
# 蛋白质 = weight_kg × _PROTEIN_PER_KG[goal_type]
# 脂肪 = target_calories × 0.25 / 9
# 碳水 = (target_calories - 蛋白热量 - 脂肪热量) / 4  补足剩余
```
方案完全符合中国 DRIs 2023 + ACSM 力量训练推荐区间，男性增肌 75kg → 112.5g=1.5g/kg（在 ISSN 1.6-2.2 下沿附近，对独居非专业健身人群合理）。

**真正的未完成任务**：`backend/tests/test_api.py` 第 715-773 行的 `test_compute_nutrition_goal_male_bulk` / `_female_cut` 两个用例的期望值仍是旧百分比方案的 `224.4` / `152.0` / `50.7`，与当前 g/kg 代码不匹配，跑测试会失败。期望值应改为：
- 男性增肌（75kg/bulk）：protein=112.5, fat=83.1, carb=448.6
- 女性减脂（58kg/cut）：protein=69.6, fat=42.2, carb=215.4

## PyCharm CreateProcess error=2 修复（venv 框架缺失）

用户截图报错：`Cannot run program 'D:\pyton_feisi\project\project_agent\backend\.venv\Scripts\python.exe': CreateProcess error=2, 系统找不到指定的文件`，调用栈卡在 `uvicorn.__init__.py`。
