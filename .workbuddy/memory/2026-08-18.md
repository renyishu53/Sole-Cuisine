## 设计立场：项目不需要联网搜索工具（如 Tavily）

- **用户提问**：项目有必要使用预定义工具（如联网搜索 Tavily）吗？
- **核实**：全仓库 grep `tavily|web_search|bind_tools|ToolNode|tools=` **零命中**（唯一匹配是 requirements 的 httptools 误报）→ 当前智能体不是 tool-calling agent，是「schema 绑定 + 确定性兜底 + 本地 RAG」。
- **结论**：核心闭环**不需要**联网搜索工具，是有意设计的「封闭域 + 离线优先 + 确定性兜底」。五条硬理由：①封闭域定位，联网会污染权威本地营养库(2043条《中国食物成分表》)这一 ground truth，破坏 Verifier 可审计性；②离线优先架构 embedding/reranker 全 `local_files_only=True` 写死，联网违背红线；③"通用知识库问答"在明确不做清单；④会击穿 EAFP 全降级 + deterministic 模式串可审计哲学；⑤独居膳食场景无成本/延迟/隐私刚需。
- **可选增强边界**：菜谱新颖性/扩充营养库/时令食材均为增强非核心；若做须满足：可选增强默认关闭、不碰核心路径、联网结果绝不进 Verifier 校验、需改用 tool-calling agent 范式(与当前 schema-bound 不同架构)。
- **面试话术**：讲成"刻意用本地 RAG 做 grounded generation，联网会引入噪声/破坏兜底/增依赖，与封闭域膳食规划定位不符"，是设计选择而非能力缺失。
