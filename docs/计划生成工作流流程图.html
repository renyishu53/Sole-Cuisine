SoloChef · 计划生成工作流（SoloChefWorkflow）

LangGraph 11 节点 StateGraph：检索 → (Supervisor) → 三领域专家并行 → Planner → Verifier → 条件回流
先回答你的问题：检索节点是「直接检索」。 图中 ② 检索节点只拿 request.prompt + goal_type 去搜，约束不参与检索 query。
约束解析在图的外面：① PlanningService.generate() 先从 DB 加载忌口/偏好/营养目标/口味画像/生活方式，注入 WorkflowState，再由 ③ ⑥ 的 meal_agent 与 verifier 消费。
降级开关：workflow_supervisor_enabled=false 时跳过 Supervisor，检索后三专家直接并行（无 LLM 派发、无回流）；domain_agents_llm_enabled=false 时专家走确定性规则引擎（不调 LLM、不调工具）。
① PlanningService.generate()（图外预处理）
从 DB 加载约束/偏好/营养目标/口味画像/生活方式 → 注入 WorkflowState；配置 checkpointer；建 agent_run 记录
▼
② retrieval 节点（直接检索，并行）
asyncio.gather：Neo4j 图谱（rewrite_query→Cypher）+ Milvus 向量（goal_type 过滤 + 可选 rerank）
→ 融合为 context 字符串；任一异常仅返回空+状态标记，不崩
▼
③ supervisor 节点（仅 workflow_supervisor_enabled）
真·LLM（ChatOpenAI, T=0）输出 JSON 派发决策；无 LLM 时降级为确定性 _fallback_dispatch（首轮全派，回流按冲突维度补派）
▼
④ meal_agent
硬约束/排除食材/备餐时长
工具：search_knowledge, get_user_profile, get_nutrition_goal, get_nutrition_report
④ shopping_agent
合并键/分类/批次
工具：search_knowledge, get_active_plan, web_research
④ budget_agent
分类限额/预留/预警
工具：search_knowledge, get_active_plan, get_nutrition_goal
+ reconcile_budget 确定性兜底
▲（并行汇聚）▼
⑤ planner 节点
融合 context + 专家建议(specialist_context) + 上轮校验反馈 + web 上下文 → LLM 生成 PlanDraft（21 餐/采购/任务/预算）
超时/异常 → DemoPlanGenerator 确定性兜底；with_meal_types + validate_weekly_meals 校验餐数
▼
⑥ verifier 节点（三级校验自愈）
采购估价回填 → 忌口(forbidden_terms)+营养目标校验 → 自动修正≤2轮 → 超预算硬冲突 → 硬冲突率>30%人工接管判定 → 产出 supervisor_feedback
▼
⑦ 条件边 verifier_route
retry_requested 且轮次/总派发未超限 → 回 ③ supervisor；否则 → END
▼
⑧ 落库（图外）
update_agent_run：trace/steps/sources/payload/checkpoint 写入 MySQL；返回 PlanningResponse
颜色： 灰 图外服务层 / 落库 蓝 检索（直接检索） 紫 Supervisor（LLM 派发） 绿 三领域专家（并行 + 工具调用） 橙 Planner（LLM 生成） 粉 Verifier（确定性校验） 深绿 条件回流控制

短期记忆（图内）：WorkflowState（单 run 内存态） + 可选 LangGraph Checkpoint（默认 InMemorySaver，支持 redis/postgres 开关，未启用）
长期记忆（跨 run）：MySQL 的 UserProfile.constraints/preferences、NutritionGoal、FeedbackRepository.taste_profile（口味画像）、plan_feedback 回流 Neo4j+向量
上下文记忆管理：生成 run 内 state 流转；对话服务走 ChatMessage 多轮历史（取最近 8 条）+ RAG + Redis SSE 事件重放（断线续传）
