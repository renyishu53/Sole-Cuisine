## 1. 本轮已经落地的代码

### 1.1 快速校准与真实 LLM 冒烟

- `GET /api/v1/ai/status` 明确返回 `llm_provider`、`llm_model`、`llm_configured`，不会把 Demo 模式描述成真实 LLM。
- `POST /api/v1/ai/llm/smoke` 只执行一次最小真实模型请求；未配置真实 Provider 和 Key 时返回 503。
- 知识库页面增加“真实 LLM 冒烟”按钮，只有真实模型已配置时可点击。
- Agent Trace 页面会读取上一次 Run，而不是每次进入页面都重新生成。

### 1.2 PostgreSQL 持久化底座

- SQLAlchemy 2.x 异步 Engine、Session 与依赖注入。
- 核心表：`users`、`families`、`family_memberships`、`agent_runs`。
- Alembic 初始迁移：`20260803_01`。
- Docker backend 启动时先执行 `alembic upgrade head`。
- `asyncpg`、`alembic` 已进入核心依赖和 `uv.lock`。

`agent_runs` 本轮完成表结构预留；将 LangGraph Run 全量写入该表属于项目完成顺序第 5 阶段。

### 1.3 JWT、家庭空间与隔离

- 手机号注册、bcrypt 密码哈希、登录、access/refresh JWT、刷新令牌。
- 注册时事务化创建 User、Family 和 owner Membership。
- 支持家庭列表、创建家庭和切换家庭；切换后换发绑定新 `family_id` 的 JWT。
- 业务接口从 JWT 获取家庭 ID，不信任前端上传的 `family_id`。
- Chroma 列表、检索、写入、删除按当前家庭过滤。
- 内存 Agent Run 查询按当前家庭过滤，跨家庭返回 404。
- 知识库写操作和真实 LLM 冒烟限制为 `owner/admin`。
- 前端登录/注册、token 自动携带、401 自动刷新、家庭切换和退出登录均已接入。

## 2. 第三方平台操作：DeepSeek

真实 LLM 调用需要你自己的 API Key。Key 属于敏感凭证，不能发送到聊天、提交 Git 或写进 `.env.example`。

### 2.1 创建 API Key

1. 浏览器进入 [DeepSeek 开放平台](https://platform.deepseek.com/)。
2. 注册或登录账号，按平台要求完成必要的账号验证。
3. 进入 API Keys 页面，创建一个仅用于 CasaMind 开发环境的 Key。
4. 创建后立即将 Key 存入本机密码管理器；平台通常不会再次完整显示。
5. 在余额/计费页面确认账户有可调用额度。
6. 不要在前端设置 `VITE_LLM_API_KEY`。以 `VITE_` 开头的变量会进入浏览器构建产物。

### 2.2 配置根目录 `.env`

打开 `D:\pyton_feisi\project\project_agent\.env`，设置：

```dotenv
LLM_PROVIDER=deepseek
LLM_API_KEY=你的真实Key
LLM_MODEL=deepseek-chat
LLM_BASE_URL=https://api.deepseek.com/v1
LLM_TIMEOUT_SECONDS=60
AI_FALLBACK_ENABLED=true
```

修改后必须完全停止并重新启动 FastAPI Debug。`get_settings()` 和 LangGraph Generator 在进程启动时创建，热刷新不应作为切换密钥的依据。

### 2.3 验证真实调用

先登录获得 access token，再调用：

```http
POST http://127.0.0.1:8000/api/v1/ai/llm/smoke
Authorization: Bearer <access_token>
```

成功响应示例：

```json
{
  "status": "connected",
  "provider": "deepseek",
  "model": "deepseek-chat",
  "latency_ms": 850,
  "message": "CASAMIND_LLM_OK"
}
```

接着调用 `POST /api/v1/plans/generate-weekly`，在返回 Trace 的 `planner.output.llm_mode` 中确认是 `deepseek`，而不是 `demo` 或 `deepseek->demo-fallback`。

## 3. 本地基础设施部署

### 3.1 启动 Docker Desktop

本次自动验证发现 Docker CLI 文件存在，但 Docker Engine 没有运行。先从 Windows 开始菜单启动 Docker Desktop，等待界面显示 Engine Running，再打开新的 PyCharm Terminal：

```powershell
$dockerBin = "C:\Program Files\Docker\Docker\resources\bin"
$env:Path = "$dockerBin;$env:Path"

docker version
docker compose version
```

`docker version` 必须同时显示 Client 和 Server。只有 Client 或提示 daemon/pipe 不存在，说明 Engine 仍未启动。

### 3.2 启动 PostgreSQL、Chroma 和 Neo4j

```powershell
cd D:\pyton_feisi\project\project_agent

docker compose up -d postgres chroma neo4j
docker compose ps
```

期望状态：

- `postgres`：`healthy`
- `chroma`：`running`
- `neo4j`：`running`

查看 PostgreSQL 日志：

```powershell
docker compose logs --tail=100 postgres
```

### 3.3 配置 PostgreSQL 与 JWT

在 PowerShell 生成随机 JWT Secret：

```powershell
$bytes = New-Object byte[] 48
[Security.Cryptography.RandomNumberGenerator]::Fill($bytes)
[Convert]::ToBase64String($bytes)
```

将输出写入根目录 `.env`，并把数据库 URL 改为：

```dotenv
DATABASE_URL=postgresql+asyncpg://casamind:casamind_password@localhost:5433/casamind
JWT_SECRET_KEY=上一步生成的随机字符串
JWT_ALGORITHM=HS256
JWT_ISSUER=casamind-api
ACCESS_TOKEN_MINUTES=30
REFRESH_TOKEN_DAYS=7
```

本地示例密码来自 `docker-compose.yml`，不能直接用于公网或生产环境。

CasaMind 使用宿主机端口 `5433`，因为当前机器的 `5432` 已被现有 `dify-db` 占用；容器之间通信仍使用 PostgreSQL 默认端口 `5432`。

## 6. Yaak 接口测试顺序

在 Yaak 建立 Environment：

```text
base_url = http://127.0.0.1:8000/api/v1
access_token = 注册或登录响应中的 access_token
refresh_token = 注册或登录响应中的 refresh_token
```

### 6.1 注册并创建首个家庭

```http
POST {{base_url}}/auth/register
Content-Type: application/json

{
  "phone": "13800000001",
  "password": "casamind123",
  "display_name": "小王",
  "family_name": "小王的家"
}
```

若手机号已注册，使用登录接口，不要反复修改数据库：

```http
POST {{base_url}}/auth/login
Content-Type: application/json

{
  "phone": "13800000001",
  "password": "casamind123"
}
```

### 6.2 验证当前身份

```http
GET {{base_url}}/auth/me
Authorization: Bearer {{access_token}}
```

确认返回的 user、family 和 role 正确。`jwt_development_secret=true` 表示仍使用开发默认密钥，应回到 `.env` 配置随机 Secret。

### 6.3 刷新 token

```http
POST {{base_url}}/auth/refresh
Content-Type: application/json

{
  "refresh_token": "{{refresh_token}}"
}
```

将响应中的新 access/refresh token 更新回 Yaak Environment。

### 6.4 创建和切换家庭

```http
POST {{base_url}}/families
Authorization: Bearer {{access_token}}
Content-Type: application/json

{
  "name": "父母家"
}
```

该接口直接返回绑定新家庭的 token。更新 Yaak token 后执行：

```http
GET {{base_url}}/families
Authorization: Bearer {{access_token}}
```

切换到已有家庭：

```http
POST {{base_url}}/families/1/switch
Authorization: Bearer {{access_token}}
```

只有当前用户属于目标家庭时才会成功，否则返回 403。

### 6.5 验证数据隔离

1. 在家庭 A 下调用 `POST /knowledge/bootstrap`。
2. 调用 `GET /knowledge`，应看到家庭 A 文档。
3. 创建或切换到家庭 B，并替换 Yaak 中的 token。
4. 再调用 `GET /knowledge`，家庭 B 初始应为空。
5. 在家庭 A 下生成计划并记录 `run_id`。
6. 使用家庭 B token 请求 `GET /agents/runs/{run_id}`，应返回 404。

不要只修改请求 JSON 中的 `family_id`。后端会忽略它并以 JWT 家庭为准，这正是隔离测试要验证的行为。

## 7. 常见问题

### `relation "users" does not exist`

数据库可连接但没有迁移：

```powershell
cd D:\pyton_feisi\project\project_agent\backend
uv run alembic upgrade head
```

### `password authentication failed for user casamind`

`.env` 的用户名/密码与 Docker Volume 中首次初始化的 PostgreSQL 凭据不一致。先检查 Compose 配置和当前连接串，不要直接删除 Volume；Volume 删除会丢失数据。

### 接口返回 401

- 检查 Header 是否为 `Authorization: Bearer <token>`。
- access token 默认 30 分钟过期，调用 `/auth/refresh`。
- 切换家庭后必须使用新响应中的 token。
- 修改 `JWT_SECRET_KEY` 后，旧 token 会全部失效，需要重新登录。

### LLM 冒烟返回 503

- `LLM_PROVIDER=demo`：这是预期行为。
- Key 为空、无额度、Base URL 错误或网络不可达：查看 FastAPI 日志中的异常类型。
- 如果周计划 Trace 显示 `deepseek->demo-fallback`，说明真实调用失败后进入 Demo 兜底，不算真实 LLM 验收通过。

### Docker 提示 daemon/pipe 不存在

Docker CLI 已找到，但 Docker Desktop Engine 未启动。启动 Docker Desktop并等待 Engine Running，再重试；这不是 Chroma、Neo4j 或 PostgreSQL 配置错误。
